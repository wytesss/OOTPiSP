2. ПЛАГИН ТОВАРИЩА И ПАПКА friend
================================================================================

В OOP lab6/friend/ лежат DLL товарища (его лабораторная на других контрактах):

  • Lab5_OOP.Contracts.dll  — интерфейс IFileCryptoPlugin (Encrypt/Decrypt)
  • XorCryptoPlugin.dll     — XOR-шифрование байтов файла, PluginId = XorCipher

Host НЕ загружает XorCryptoPlugin.dll напрямую в PluginLoader: у него другой
контракт (не ISerializationProcessingPlugin). Вместо этого:

  1) Сборка копирует friend/*.dll в bin/.../Plugins/Friend/
  2) Наш lab6.Plugin.XorCryptoAdapter.dll регистрируется как обычный плагин
  3) Адаптер внутри подгружает XorCryptoPlugin из Plugins/Friend/

3. ПАТТЕРН «АДАПТЕР» — КАК ПОДКЛЮЧЁН XORCRYPTO
================================================================================

Теория:
  Адаптер переводит один интерфейс в другой, чтобы несовместимые модули
  работали вместе без переписывания чужого кода.

Практика:

  «Клиент» (наш host) ожидает:
    ISerializationProcessingPlugin
      ProcessBeforeSave / ProcessAfterLoad
      ProcessingTypeId, DisplayName

  «Адаптируемый» (товарищ) предоставляет:
    IFileCryptoPlugin
      Encrypt(byte[]) / Decrypt(byte[])

  Адаптер: lab6.Plugin.XorCryptoAdapter/XorCryptoAdapterPlugin.cs
    • ProcessBeforeSave → FriendPluginHost.Encrypt(ItemsPayload)
    • перед десериализацией → Decrypt (интерфейс IItemsPayloadPreprocessor)
    • в metadata пишется ключ xorCipher = XorCipher

  Загрузка DLL товарища: FriendPluginHost.cs
    • отдельный AssemblyLoadContext
    • рефлексия: тип XorCryptoPlugin.XorCipherPlugin, вызов Encrypt/Decrypt

Уместность:
  Контракты lab5/lab6 и Lab5_OOP.Contracts разные; переписывать плагин друга
  не нужно — достаточно тонкого адаптера в своей solution.

5. ПАТТЕРНЫ «РЕЕСТР» И «ФАБРИКА» (LAB5 И LAB6 — ОДИНАКОВО)
================================================================================

--- 5.1. Реестр (Registry) ---

Теория:
  Центральное место регистрации «типов по id» с последующим поиском.
  Добавление новых элементов без изменения клиентского кода.

Практика в lab5 и lab6:

  A) VehicleTypeRegistry (lab5/Domain или lab6/Domain/VehicleTypeRegistry.cs)
     • RegisterBuiltIn — встроенные Car, Bus, Truck, Van
     • RegisterFromPlugin — типы из IVehiclePlugin (Motorcycle)
     • Types — список для ComboBox на форме
     • PluginLoader после загрузки DLL вызывает RegisterFromPlugin

  B) SerializationPluginRegistry (Plugins/SerializationPluginRegistry.cs)
     • Register(ISerializationProcessingPlugin) при загрузке DLL
     • GetEnabled(ids) — только включённые в appsettings.json
     • Используется в VehicleBsonSerializer при save/load

--- 5.2. Фабрика (Factory) ---

Теория:
  Создание объектов без new КонкретныйКласс() в клиенте — через функцию
  или метод «создай по идентификатору типа».

Практика в lab5 и lab6:

  A) VehicleTypeInfo.Factory (lab5.Contracts/Domain/Vehicle.cs)
     • Поле Func<Vehicle> Factory у каждой записи реестра типов
     • При регистрации передаётся лямбда: () => new Car(), () => new Motorcycle()

  B) Form1.buttonAdd_Click (Form1.cs)
     • Vehicle vehicle = info.Factory();
     • UI не знает, Car это или Motorcycle — только вызывает фабрику из реестра

  C) VehicleBootstrap (Domain/VehicleBootstrap.cs)
     • Регистрирует встроенные фабрики: () => new Car() и т.д.

  D) Плагин Motorcycle (MotorcyclePlugin.Register)
     • В контекст передаёт factory: () => new Motorcycle()

Итого для ответа преподавателю:
  «Реестр — VehicleTypeRegistry и SerializationPluginRegistry.
   Фабрика — Func<Vehicle> в VehicleTypeInfo, вызов info.Factory() в Form1.»

8. СОХРАНЕНИЕ С XOR И CHECKSUM — ПОРЯДОК
================================================================================

Важно: checksum должен считаться от НЕзашифрованных данных.

При включённых checksum и xor-cipher (порядок в EnabledProcessingIds):

  Сохранение:
    1) itemsPayload = сериализация списка ТС
    2) checksum: hash(itemsPayload) → metadata["checksum"]
    3) xor-cipher: itemsPayload = Encrypt(itemsPayload), metadata["xorCipher"]

  Загрузка:
    1) прочитать зашифрованные bytes из items
    2) xor-cipher: Decrypt → открытые bytes
    3) десериализация в List<Vehicle>
    4) checksum: сравнить hash(открытые bytes) с metadata["checksum"]

Файл vehicles.bson (логически):
  items     — бинарный блок (после XOR — шифротекст)
  checksum  — hex SHA-256 от исходных (до XOR) байтов списка
  xorCipher — метка "XorCipher" если применялось шифрование
