2. ТЕОРИЯ (ПРОСТЫМИ СЛОВАМИ) И СВЯЗЬ С ПРАКТИКОЙ
================================================================================

--- 2.1. Иерархия классов и полиморфизм ---

Теория: базовый класс определяет общий контракт (методы GetInfo, Edit),
производные классы реализуют специфику. Полиморфизм позволяет работать
с любым транспортным средством через ссылку на базовый класс.

Практика:
  - Vehicle — абстрактный, содержит Id, Name, Year, абстрактные GetInfo() и Edit().
  - PassengerVehicle : Vehicle — добавляет PassengerCapacity.
  - CargoVehicle : Vehicle — добавляет MaxLoadKg.
  - Встроенные: Car, Bus, Truck, Van.
  - Плагинный: Motorcycle : PassengerVehicle.

--- 2.2. Что такое плагин и контракт? ---

Теория: основная программа (host) не знает конкретные классы плагинов,
но знает интерфейс, который те должны реализовать. Host загружает сборку,
находит типы, реализующие интерфейс, и вызывает их методы.

Практика:
  - Контракт (общая библиотека) — lab4.Contracts.dll.
  - Интерфейс IVehiclePlugin: метод Register(VehiclePluginContext context).
  - Плагин MotorcyclePlugin реализует этот интерфейс.
  - Host через рефлексию находит все классы, реализующие IVehiclePlugin,
    создаёт экземпляр и вызывает Register.

--- 2.3. Рефлексия (Reflection) ---

Теория: механизм, позволяющий во время выполнения исследовать структуру
сборок, типов, создавать объекты по именам, вызывать методы.

Практика (PluginLoader.cs):
  Assembly assembly = Assembly.LoadFrom(dllPath);
  var pluginTypes = assembly.GetTypes().Where(t => typeof(IVehiclePlugin).IsAssignableFrom(t));
  IVehiclePlugin plugin = (IVehiclePlugin)Activator.CreateInstance(type);
  plugin.Register(context);

--- 2.4. Реестр типов (VehicleTypeRegistry) ---

Теория: центральное хранилище, которое знает обо всех доступных типах
(и встроенных, и плагинных). Каждый тип представлен фабрикой (Func<Vehicle>),
которая умеет создавать экземпляр.

Практика:
  - RegisterBuiltIn("car", "Car", () => new Car())
  - RegisterFromPlugin(pluginName, "motorcycle", "Motorcycle (plugin)", () => new Motorcycle())
  - Типы используются для заполнения выпадающего списка и создания объектов.

--- 2.5. Сериализация с полиморфизмом (MongoDB.Bson) ---

Теория: при сохранении списка объектов базового класса нужно сохранить
реальный тип каждого объекта. Используется дискриминатор — метка, указывающая,
какой именно производный класс был сохранён.

Практика (VehicleBsonSerializer.cs):
  - Корневой класс Vehicle помечается как IsRootClass и получает дискриминатор "vehicle".
  - Каждый производный класс регистрируется с уникальным дискриминатором
    ("car", "bus", "truck", "van", "motorcycle").
  - При десериализации BSON-драйвер читает дискриминатор и создаёт правильный тип.

4. КАК ВСЁ СВЯЗАНО ПРИ ЗАПУСКЕ (ПОШАГОВО)
================================================================================

Шаг 1. Program.Main
  • VehicleBootstrap.RegisterBuiltInTypes() — регистрирует Car, Bus, Truck, Van
    в VehicleTypeRegistry и в VehicleBsonSerializer (дискриминаторы).
  • PluginLoader.LoadAll(args) — загружает плагины из папки Plugins и/или
    из аргументов командной строки (например, --plugin MyPlugin.dll).
  • Application.Run(new Form1()) — запуск главного окна.

Шаг 2. Form1 при открытии
  • Инициализирует привязку данных (BindingList<Vehicle> для ListBox).
  • Загружает список машин из файла vehicles.bson (если есть) через
    VehicleBsonSerializer.LoadFromFile.
  • Заполняет комбобокс comboVehicleTypes типами из VehicleTypeRegistry.Types.
  • Обновляет статус плагинов (labelPlugins) на основе VehicleTypeRegistry.LoadedPlugins.

Шаг 3. Пользователь добавляет ТС
  • Выбирает тип в ComboBox (например, "Car" или "Motorcycle (plugin)").
  • По кнопке "Add" вызывается info.Factory(), создаётся объект.
  • Вызывается vehicle.Edit() — открываются диалоги InputBox для ввода характеристик.
  • Объект добавляется в список _vehicles (BindingList).

Шаг 4. Редактирование / удаление
  • Выделенный объект редактируется через vehicle.Edit() (полиморфизм).
  • Удаление — _vehicles.Remove(selected).

Шаг 5. Сохранение (Serialize)
  • VehicleBsonSerializer.SaveToFile(FilePath, _vehicles.ToList()).

Шаг 6. Загрузка (Deserialize)
  • var loaded = VehicleBsonSerializer.LoadFromFile(FilePath);
  • _vehicles.Clear(); foreach(var v in loaded) _vehicles.Add(v);

Шаг 7. Перезагрузка плагинов (кнопка Reload plugins)
  • Очищаем реестр типов (VehicleTypeRegistry.Clear()).
  • Перерегистрируем встроенные типы.
  • Заново загружаем плагины через PluginLoader.LoadAll().
  • Обновляем комбобокс и статус.

5. ПЛАГИН ТИПОВ (Motorcycle) — ПОШАГОВО
================================================================================

Плагин — это отдельная DLL, которая ссылается на lab4.Contracts.

--- Файл Motorcycle.cs ---
[Serializable]
public class Motorcycle : PassengerVehicle
{
    public bool HasSidecar { get; set; }

    public override string GetInfo() => $"{Name}, year {Year}, seats {PassengerCapacity}, sidecar: {(HasSidecar ? "yes" : "no")}";

    public override void Edit()
    {
        // Запрашиваем Name, Year через базовый EditCommon
        // Запрашиваем PassengerCapacity через EditPassengerCapacity
        // Запрашиваем HasSidecar через InputBox
    }
}

--- Файл MotorcyclePlugin.cs ---
public class MotorcyclePlugin : IVehiclePlugin
{
    public string Name => "Motorcycle plugin";

    public void Register(VehiclePluginContext context)
    {
        // Регистрируем тип в реестре
        context.RegisterVehicleType("motorcycle", "Motorcycle (plugin)", () => new Motorcycle());
        // Регистрируем дискриминатор для сериализации
        context.RegisterBsonType<Motorcycle>("motorcycle");
    }
}

Что делает host при загрузке:
  1) Загружает DLL.
  2) Находит класс MotorcyclePlugin.
  3) Создаёт экземпляр.
  4) Вызывает Register, передавая контекст.
  5) Контекст вызывает методы регистрации в реестре типов и в сериализаторе.

После этого:
  - В комбобоксе появляется "Motorcycle (plugin)".
  - При выборе этого пункта фабрика () => new Motorcycle() создаст объект.
  - Объекты Motorcycle корректно сохраняются и загружаются (благодаря RegisterBsonType).

6. РЕГИСТРАЦИЯ ВСТРОЕННЫХ ТИПОВ И РЕЕСТР
================================================================================

--- VehicleTypeRegistry.cs ---
Статический класс, хранит список VehicleTypeInfo.

  public static void RegisterBuiltIn(string id, string displayName, Func<Vehicle> factory)
  {
      Register(id, displayName, factory, "Built-in");
  }

  public static void RegisterFromPlugin(string pluginName, string id, string displayName, Func<Vehicle> factory)
  {
      Register(id, displayName, factory, pluginName);
      _loadedPlugins.Add(pluginName);
  }

При регистрации проверяется уникальность id, чтобы не было конфликта.

--- VehicleBootstrap.cs ---
  RegisterBuiltInTypes() — вызывается в Program.Main.
  Регистрирует Car, Bus, Truck, Van и их дискриминаторы.

--- Почему реестр отдельно от UI? ---
UI (Form1) просто привязывается к VehicleTypeRegistry.Types.
Если добавить новый тип через плагин, комбобокс обновляется автоматически
(после вызова RefreshVehicleTypes).

7. ДИНАМИЧЕСКАЯ ЗАГРУЗКА DLL (ИЗ ПАПКИ И КОМАНДНОЙ СТРОКИ)
================================================================================

Класс PluginLoader (файл lab4/Plugins/PluginLoader.cs).

--- Автозагрузка из папки Plugins ---
  string pluginsDir = Path.Combine(AppContext.BaseDirectory, "Plugins");
  if (Directory.Exists(pluginsDir))
  {
      foreach (string dllPath in Directory.EnumerateFiles(pluginsDir, "*.dll"))
      {
          TryLoadAssembly(dllPath, errors, loadedAssemblies);
      }
  }

--- Аргументы командной строки ---
Поддерживаются --plugin или -p:
  lab4.exe --plugin C:\MyPlugin.dll
  lab4.exe -p MyPlugin.dll

Если указано только имя (без пути), ищется сначала в текущей папке, затем в папке Plugins.

--- Загрузка сборки и поиск плагинов ---
  Assembly assembly = Assembly.LoadFrom(fullPath);
  var pluginTypes = assembly.GetTypes().Where(t => typeof(IVehiclePlugin).IsAssignableFrom(t));

  foreach (var type in pluginTypes)
  {
      var plugin = (IVehiclePlugin)Activator.CreateInstance(type);
      var context = new VehiclePluginContext(
          (id, displayName, factory) => VehicleTypeRegistry.RegisterFromPlugin(plugin.Name, id, displayName, factory),
          (vehicleType, discriminator) => VehicleBsonSerializer.RegisterDerivedGeneric(vehicleType, discriminator)
      );
      plugin.Register(context);
  }

--- Обработка ошибок ---
Исключения перехватываются и добавляются в список LoadErrors.
Пользователь видит предупреждения, но программа продолжает работу.

--- Кнопка "Reload plugins" в Form1 ---
Очищает реестр, перерегистрирует встроенные типы, заново загружает плагины.
Это демонстрирует, что добавление/удаление DLL в папку Plugins можно делать
без перезапуска приложения (нажал кнопку — и новые типы появились).

8. СЕРИАЛИЗАЦИЯ С ПОДДЕРЖКОЙ ДИСКРИМИНАТОРОВ (MongoDB.Bson)
================================================================================

Класс VehicleBsonSerializer (lab4/Serialization/VehicleBsonSerializer.cs).

--- Настройка корневого класса Vehicle ---
  BsonClassMap.RegisterClassMap<Vehicle>(cm =>
  {
      cm.AutoMap();
      cm.SetIsRootClass(true);
      cm.SetDiscriminator("vehicle");
  });

--- Регистрация производных классов ---
  public static void RegisterDerived<T>(string discriminator) where T : Vehicle
  {
      BsonClassMap.RegisterClassMap<T>(cm =>
      {
          cm.AutoMap();
          cm.SetDiscriminator(discriminator);
      });
  }

Пример: RegisterDerived<Motorcycle>("motorcycle")

--- Формат файла vehicles.bson ---
При сохранении создаётся BSON-документ:
  {
    "items": [ <объект Vehicle>, <объект Car>, ... ]
  }

Каждый объект внутри массива содержит поле "_t" (дискриминатор), например:
  { "_t": "car", "Name": "Tesla", "Year": 2023, "PassengerCapacity": 5, "HasAirConditioning": true }

При загрузке драйвер смотрит на "_t" и создаёт объект нужного типа.

--- Совместимость с lab2/lab3 ---
Файл сохраняется в том же формате, что и раньше (массив объектов). Поэтому
старые файлы должны читаться (если в них нет полей, специфичных для новых типов,
то они заполняются значениями по умолчанию).

  private readonly BindingList<Vehicle> _vehicles = new();

BindingList автоматически уведомляет ListBox об изменениях (добавление, удаление,
изменение). При вызове _vehicles.ResetItem(index) обновляется отображение после
редактирования.

  comboVehicleTypes.DataSource = VehicleTypeRegistry.Types.ToList();

Каждый элемент — VehicleTypeInfo. При выборе пользователь получает фабрику.

--- Добавление нового объекта ---
  Vehicle vehicle = info.Factory();

  UpdatePluginStatus() — обновляет labelPlugins (имена загруженных плагинов).

Для сдачи достаточно:
  - Показать, что при запуске программы в комбобоксе есть "Motorcycle (plugin)".
  - Создать объект Motorcycle, заполнить его, сохранить в файл, перезагрузить — данные сохраняются.
  - Показать код плагина и объяснить, как host его находит и регистрирует.
  - Продемонстрировать перезагрузку плагинов (удалить/добавить DLL и нажать Reload plugins).
