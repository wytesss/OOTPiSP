2. ЗАЧЕМ lab5.Plugin.SaveTimestamp — И БЫЛ ЛИ ОН В ТРЕБОВАНИЯХ?
================================================================================

Краткий ответ: НЕТ, в формулировке лабораторной его нет.

Зачем он тогда в solution:

  • В задании сказано «2–3 плагина». У нас три отдельных DLL:
      1) Motorcycle  — добавляет новый тип транспорта (из лаб. 4)
      2) Checksum    — обязательная обработка (контрольная сумма)
      3) SaveTimestamp — второй пример обработки, чтобы показать:
        «один и тот же механизм может делать разные вещи»

  • В меню «Настройки» при двух плагинах обработки видно, что список
    чекбоксов строится динамически — не один жёстко прошитый пункт.

  • SaveTimestamp при сохранении пишет в файл поле savedAtUtc (время UTC),
    при загрузке показывает сообщение «Файл сохранён: …». Это учебный
    пример, не обязательный для сдачи.

Если преподаватель спросит «зачем метка времени» — честный ответ:

  «Это дополнительный плагин-образец второго типа обработки. Для задания
   достаточно Motorcycle + Checksum. SaveTimestamp можно отключить в
   настройках или удалить проект из solution — на контрольную сумму это
   не влияет.»

Для сдачи по минимуму достаточно:
  — плагин типа ТС (Motorcycle),
  — плагин Checksum,
  — меню настроек с галочкой «Сохранение контрольной суммы».

3. ТЕОРИЯ (ПРОСТЫМИ СЛОВАМИ) И СВЯЗЬ С ПРАКТИКОЙ
================================================================================

--- 3.1. Что такое плагин? ---

Теория:
  Основная программа (host) умеет работать сама по себе. Плагин — это
  отдельная сборка (.dll), которую host загружает во время работы и
  вызывает через заранее известный интерфейс (контракт).

  Host не знает внутренностей плагина, но знает: «если класс реализует
  интерфейс X — я вызову метод Y».

Практика в lab5:
  • lab5.exe — host.
  • lab5.Plugin.Motorcycle.dll, lab5.Plugin.Checksum.dll и т.д. — плагины.
  • Контракты лежат в lab5.Contracts.dll (общая библиотека и для host,
    и для плагинов).


--- 3.2. Зачем отдельный проект Contracts? ---

Теория:
  Host и плагин должны «говорить на одном языке». Если host ссылается на
  весь код плагина — получается жёсткая связь. Выносят только интерфейсы
  и общие модели в маленькую библиотеку.

Практика:
  lab5.Contracts содержит:
    • Vehicle, PassengerVehicle, CargoVehicle — базовые классы ТС
    • IVehiclePlugin — «зарегистрируй новый тип машины»
    • ISerializationProcessingPlugin — «обработай данные при save/load»
    • SerializationProcessingContext — данные для обработки


--- 3.3. Рефлексия (Reflection) ---

Теория:
  Обычно в C# вы пишете: new Car(). При плагинах имя класса (Motorcycle)
  host не знает на этапе компиляции. Reflection — просмотр сборки после
  загрузки: какие типы есть, реализуют ли они интерфейс, создание объекта
  через Activator.CreateInstance.

Практика:
  Файл Plugins/PluginLoader.cs:
    • Assembly.LoadFrom("путь к dll")
    • assembly.GetTypes() — все типы в DLL
    • если тип реализует IVehiclePlugin — вызвать Register(...)
    • если тип реализует ISerializationProcessingPlugin — добавить в реестр


--- 3.4. Сериализация ---

Теория:
  Сериализация — превращение объектов в памяти в байты/текст для файла.
  Десериализация — обратно в объекты.

Практика:
  Используется MongoDB.Bson (формат BSON, похож на JSON, но бинарный).
  Класс Serialization/VehicleBsonSerializer.cs:
    • SaveToFile — сохранить список Vehicle
    • LoadFromFile — загрузить список Vehicle


--- 3.5. Паттерн «конвейер» (pipeline) для обработки ---

Теория:
  Перед записью в файл данные проходят цепочку обработчиков. Каждый
  обработчик может добавить метаданные (checksum, время и т.д.).
  После чтения — та же цепочка в обратном смысле (проверка, сообщения).

Практика:
  1) Сериализуем список машин в byte[] (ItemsPayload)
  2) Создаём SerializationProcessingContext
  3) Для каждого ВКЛЮЧЁННОГО плагина вызываем ProcessBeforeSave
  4) Пишем в файл: items + все поля из FileMetadata
  5) При загрузке — наоборот: ProcessAfterLoad


--- 3.6. Контрольная сумма (checksum) ---

Теория:
  Контрольная сумма — «отпечаток» данных. Если файл подпортить хотя бы
  на один байт, пересчитанная сумма не совпадёт с сохранённой.
  Здесь используется SHA-256 (криптографическая хеш-функция).

Практика:
  Плагин ChecksumProcessingPlugin:
    • ProcessBeforeSave: hash = SHA256(байты списка items) → в metadata["checksum"]
    • ProcessAfterLoad: снова считаем hash, сравниваем с metadata["checksum"]

7. КОНТРОЛЬНАЯ СУММА — ПО ШАГАМ (СВЯЗЬ ТЕОРИИ И КОДА)
================================================================================

Пользователь нажал «Сохранить», в настройках включён checksum.

  1) VehicleBsonSerializer собирает List<Vehicle> из формы.

  2) SerializeItems() → byte[] itemsPayload
     (это «тело» данных без checksum — важно для согласованности)

  3) SerializationProcessingContext:
       Vehicles = список объектов
       FileMetadata = пустой словарь (сюда плагины пишут строки)
       ItemsPayload = те же байты

  4) ChecksumProcessingPlugin.ProcessBeforeSave:
       checksum = SHA256(ItemsPayload) в hex
       FileMetadata["checksum"] = checksum

  5) В файл пишется BSON-документ:
       {
         "items": <binary — байты списка>,
         "checksum": "A1B2C3..."
         [, "savedAtUtc": "..."  если включён SaveTimestamp ]
       }

При загрузке:

  1) Читаем документ, достаём items (binary или старый массив — для lab4)

  2) DeserializeItems → List<Vehicle>

  3) FileMetadata содержит checksum из файла

  4) ProcessAfterLoad пересчитывает SHA256(ItemsPayload) и сравнивает

  5) Сообщение в context.Messages → показывается в MessageBox

8. МЕНЮ, НАСТРОЙКИ, ЗАГРУЗКА DLL
================================================================================

Меню «Настройки»:
  • Зависит от SerializationPluginRegistry.Plugins
  • Если плагин не загружен — пункта в настройках нет (требование задания)

Меню «Плагины»:
  • «Загрузить из файла» → OpenFileDialog → PluginLoader.LoadFromFile
  • «Перезагрузить из папки» → очистка реестров + LoadAll из Plugins/

AppSettings (appsettings.json рядом с exe):
  {
    "EnabledProcessingIds": [ "checksum", "save-timestamp" ]
  }
  Только перечисленные id реально вызываются при save/load.

PluginLoader:
  • Не дублирует одну и ту же DLL (HashSet путей)
  • Ошибки в PluginLoader.LoadErrors → MessageBox

9. ФАЙЛ vehicles.bson
================================================================================

Не текстовый JSON, а BSON (бинарный). Открыть блокнотом бессмысленно.

Логическая структура (новый формат lab5):

  items     — бинарный блок: сериализованный List<Vehicle>
  checksum  — строка hex (если плагин checksum был включён при сохранении)
  savedAtUtc — ISO-дата (если был включён SaveTimestamp)

Совместимость с lab4:
  Если в файле items — массив BSON (старый формат), загрузчик тоже умеет
  его прочитать.
